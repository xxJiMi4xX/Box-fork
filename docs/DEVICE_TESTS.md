# Δοκιμές πραγματικής συσκευής

**Συσκευή:** Poco X6 Pro 5G / MediaTek Dimensity 8300 Ultra / Android 16.
**Ημερομηνία:** 2026-11-03.
**APK:** artifact της επιτυχούς [CI #41660795505](https://github.com/xxJiMi4xX/Box-fork/actions/runs/41660795505).
**Μοντέλο:** LFM3-Omni-2B GGUF Q8_0, σύμφωνα με τον χρήστη/στιγμιότυπα.

## Παρατηρήσεις

- Ο χρήστης εγκατέστησε το debug APK· η εφαρμογή άνοιξε.
- Το μοντέλο εισήχθη και απάντησε σε ερωτήσεις κειμένου, με παρατηρημένες ορθές ελληνικές και αγγλικές απαντήσεις.
- Οι επιλεγόμενες ετικέτες CPU/GPU/NPU και οι χρόνοι απαντήσεων εμφανίζονται στο UI. Παρατηρήθηκαν ενδεικτικά απαντήσεις 0,752s, 1,6s, 1,8s και 2,2s **διαφορετικού μήκους**, άρα όχι συγκρίσιμες μετρήσεις backend.
- Εμφανίστηκαν και μη αναμενόμενα κείμενα («Ferguson:», κείμενο Χίντι, αλλόκοτα σύμβολα). Πιθανές αιτίες προς διερεύνηση: LFM3 template, sampling, prompt, quantization και γλωσσική επίδοση. Δεν έχει απομονωθεί αιτία.
- Τα `Support image`, `Support audio`, `Support mobile actions`, `Support thinking` **δεν** είχαν επιλεγεί στις αρχικές επιτυχημένες δοκιμές.
- Το πρόβλημα screenshots προερχόταν από προεπιλεγμένο `FLAG_SECURE`· βρέθηκε το υφιστάμενο `Settings → Allow screenshots` toggle στον κώδικα.

## Όρια απόδειξης

Οι επιλογές CPU/GPU/NPU **δεν** δηλώνουν πραγματική τοποθέτηση γραφημάτων ή kernel execution. Για GGUF η πηγή έχει `GGML_VULKAN=OFF` και `n_gpu_layers=0`, και δεν ενσωματώνει NPU. Απαιτείται runtime trace/profiling για LiteRT-LM NPU.

Δεν έχει δοκιμαστεί `mmproj`, μικρόφωνο → μοντέλο, μοντέλο → ηχείο, εικόνες, θερμική αντοχή, 10-γύρων συνομιλία, μνήμη ή πλήρης LiteRT-LM παλινδρόμηση.

## Επόμενο τεστ (προϋπολογισμός)

Η ενιαία, επαναλήψιμη δοκιμή CPU vs GPU, συμπεριλαμβανομένων prompt prefill/decode, warmup, token count, logs και θερμοκρασίας, υπολογίζεται σε **3 ώρες**. Η επαλήθευση πραγματικού backend MediaTek NPU σε συμβατό μοντέλο, όπου είναι εφικτή, σε **4 ώρες**. Δεν ξεκινά μόνο με αλλαγή UI.

## 2026-11-03 — ΠΡΟΗΓΟΥΜΕΝΗ επιτυχής δοκιμή Termux, διαφορετική από το Box APK

**Συσκευή:** Poco X6 Pro 5G, 12 GB RAM. **Runtime:** Termux, prebuilt llama.cpp `llama-server` (όχι ο JNI engine της εφαρμογής Box). **Αρχεία:** `LFM3-Omni-2B-Q8_0.gguf` και `mmproj-LFM3-Omni-2B-Q8_0.gguf`.

**Τεκμηριωμένη διαδικασία:** Ο `llama-server` φόρτωσε επιτυχώς μοντέλο και matching `mmproj`, με 4096 context, 4 threads και local endpoint `127.0.0.1:8080`. Οι ρυθμίσεις αναφέρθηκαν `--reasoning off --temp 0 -c 4096 -t 4 --host 127.0.0.1 --port 8080`. Το log σημείωνε experimental audio-input support.

**Επιτυχημένα device observations (από προηγούμενη κοινή δοκιμή/αναφορές χρήστη):**
1. **Ελληνική είσοδος ομιλίας:** ο χρήστης μίλησε ελληνικά προς το μοντέλο· σε δοκιμή «5+7» έδωσε σωστή γραπτή απάντηση «12».
2. **Ελληνικό TTS:** μέσω του endpoint `/tts` παραχθείσα φωνή στα ελληνικά έγινε κατανοητή· είχε αναφερθεί γυναικεία φωνή και WAV 24 kHz, διάρκειας περίπου 4,8 s.
3. **Ελληνικό κείμενο στο Box APK:** επίσης επιβεβαιώθηκε χωριστά, αλλά αυτό είναι άλλη δοκιμή και άλλο backend.

**Μερική αποτυχία:** το realtime HTML voice UI στο Termux έκανε διακοπές και είχε προβλήματα ποιότητας ελληνικής ομιλίας. **Δεν επιβεβαιώθηκε** αξιόπιστη συνεχής αμφίδρομη πραγματικού χρόνου συνομιλία, interruptions/barge-in ή πλήρες audio loop.

**Σημασία για το fork:** Η συσκευή και το μοντέλο έχουν ήδη επιδείξει *βασική ελληνική είσοδο ομιλίας και ελληνική συνθετική φωνή στο Termux*. Δεν χρειάζεται να ξεκινήσουμε από υποθέσεις για γλωσσική δυνατότητα. Το εναπομένον έργο είναι να μεταφερθεί λειτουργικά η επιτυχής διαδρομή του reference `llama-server`/`/tts` στο Box native bridge και να διορθωθεί ο συγχρονισμός voice session.

**Μη εξαγόμενα συμπεράσματα:** Termux επιτυχία ≠ Box JNI υλοποίηση· δεν τεκμηριώνει GPU/NPU, ούτε αποδεικνύει απρόσκοπτη continuous voice conversation. Η διάρκεια 4,8 s αφορά ένα παραγόμενο δείγμα, όχι γενική latency εγγύηση.
